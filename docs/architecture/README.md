# 系统架构

职责：描述跨功能的系统结构、契约和当前状态，AI 在代码或配置改变后维护。功能级设计引用 [TECH 真源](../specs/prds/)。

| 分类 | 内容 |
|---|---|
| [整体结构](overview/) | 系统边界、应用和依赖 |
| [接口契约](api/) | API、调用方、错误与兼容 |
| [数据结构](schema/) | 数据库、缓存、迁移 |
| [组件与模块](components/) | 复用、依赖和职责边界 |
| [流程与时序](flows/) | 状态变化、Prompt 与外置逻辑 |
| [安全与权限](security/) | 身份、数据访问和审计 |
| [环境与部署](deployment/) | 配置来源、端口、发布与环境差异 |
| [架构决策](decisions/) | ADR、已批准结论和理由 |

接口/schema/组件/流程/权限/环境/Prompt 结构改变时，更新受影响内容与来源链接。已实现、计划、待验证分别标记。架构取舍仍需按现有规则决策，不能自动批准。

当前尚未登记项目架构；目录齐全不代表上述能力已实现。
